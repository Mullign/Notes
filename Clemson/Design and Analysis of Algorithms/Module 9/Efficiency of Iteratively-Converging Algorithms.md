![[Efficiency of Iteratively-Converging Algorithms.pdf]]Many algorithms, especially those within the realm of continuous optimization, converge iteratively towards an optimal solution. They get closer and closer over time, and they may not even reach the exact value of the optimal solution. To analyze the performance of these algorithms, we do need a slightly different vocabulary than we have been using in the past for the predominantly exact discrete algorithms we've mostly focused on. So let's spend just a few minutes talking about characterizing performance of iteratively converging algorithms. As a very simple example, let's find the square root of 2. So I have a function f of x that gives me x squared. I'd like to find the value of x that I can plug into that function such that the output is 2. 

Basically, I want to invert that function. This is actually a fairly common phenomenon. I have a forward process that is straightforward, squaring something, but the inverse of that process is not as straightforward, taking the square root of something. And in this case, I'm lucky because x squared is a monotonically increasing function. So I'll actually be able to basically binary search on x to find the right value that inverts this process. This actually can be a useful idea in many other situations. Suppose you have an elaborate simulation that you plug in a bunch of input parameters into, and the simulation proceeds in a straightforward, maybe a complicated way, but at least a straightforward way in the forward direction and then gives you some output, but it may be much harder to invert that process given the output, what were the inputs that led to that output. 

And as long as your simulation is monotonic, it's kind of a monotonic function of its input, you can sometimes get by with a binary search on those inputs to find what inputs would have led to a particular output. So let's maybe draw a picture of what's happening here and talk about how we characterize convergence rate in this situation. So if I switch over to the whiteboard, here's my coordinate axis. Generically, I have this function. It's going to be an increasing function. We call that function f, and I have some sort of a target value. We'll call that y, and I would like to find a value of x such that f of x evaluates to y. 

So let's call this target value x star. So I'm looking for x star such that when I evaluate f at that point, I get my target of y. So how do I do that? Well, if f is indeed an increasing function, binary search is a very straightforward way of accomplishing this feat. So I can maybe search an interval that starts at a and ends at b. So I've kind of bracketed my optimal solution x star between a and b. And every step of the binary search, of course, I'm going to look at the midpoint of that range. 

So I'll look at a value of x, which is the average of a and b, and then I can evaluate f at that value of x. And by comparing that to y, I can figure out if my guess was too high or too low, and then I can restrict my search to the first or the second half and keep doing that. So very straightforward. We've seen binary search many times in this class to date. So how do I talk about convergence of this process? Well, one easy way to do that is to look at basically the error in my current guess. So look at the distance between x and x star. 

One nice way to bound that, very simply, is to just say that that is at most the size of my current interval. It's at most b minus a. And every single step of binary search, of course, takes b minus a, the size of my interval, and reduces that to half of its current value. So the error in my distance to the optimal solution is dropping by a factor of two. It's halving itself in each iteration. So error is exponentially decreasing over time. That's really good news. 

So binary search is actually a pretty powerful way to home in on the optimal solution in this situation. Let's maybe look at another way of characterizing convergence rate in this time. So what we've just done is said that the error rate decreases exponentially over time. That's a very common way we talk about convergence as kind of a decrease in error. Another way that we can talk about convergence is an increase in precision. So suppose, just to kind of put some concrete numbers on things, that I'm searching an interval from, say, zero up to eight. And I'm trying to find x star within that interval. 

So x star, if I were to write it in, say, binary, it would consist of three binary digits, and then a decimal point, and then a number of additional binary digits, if x star does live in that range. So if I do a binary search on that range, then I cut the range in half, basically. And in my first step, I can tell, does x star live in the first half or the second half? Let's just say that it lives in the second half. And so if that's the case, I know the first digit of x star is going to be a one, not a zero. And then suppose the next iteration of binary search takes that second half, divides it in half, and decides that, oh, x lives in the first part of that sub range. In that case, I know that the second digit of x star is going to be a zero, and so on. 

This is why I've written x star in binary, because each step of binary search is going to fill in one additional digit worth of precision in x star. So my knowledge of x star basically gets more and more precise by one digit in each iteration. And so we sometimes call this linear convergence, because the amount of precision in my answer is increasing at a linear rate over time. So that's another way that we can characterize convergence, is the rate of increase in precision and accuracy of my answer. So let's go back to my slide view here and kind of talk about that in a little bit more detail. So two outlooks on convergence rate. One is decreasing in error rate. 

Another is increase in precision. The exact example on the preceding slide on the whiteboard, we call that linear convergence, because the accuracy increases at a linear rate. It's a little bit more confusing to think about it in terms of decrease of error, because the error is actually decreasing at an exponential rate. So it's kind of confusing to a lot of people to call that linear convergence, but it's called linear convergence because you're adding precision at a linear rate in that situation. Another way to characterize convergence is to kind of flip things around and basically ask for the number of iterations that you need in order to achieve a desired reduction in error. So let's suppose I have some initial error and I'd like to reduce that to an epsilon fraction of what it initially was. So I can say how many iterations are needed to do that, to achieve an epsilon fraction reduction in error rate. 

If I have a linear rate of convergence, then it's pretty easy to do the math and figure out that the number of steps you need is on the order of log of one over epsilon in order to achieve an epsilon factor reduction in your error rate. So these are kind of perhaps the most two common ways that we talk about convergence, either reduction in the rate of reduction of error, the rate of addition of precision, or the number of iterations needed to achieve a desired reduction in error. If we look at this in the context of an optimization problem, it's the same idea. You'd like to find some sort of a value x star that minimizes the function x. And so we'd like to talk about convergence rate, either in terms of decrease in error over time or increase in precision over time or number of steps required to reduce the error to an epsilon fraction of its initial value. The only thing here is what is the error? There's kind of two common ways to measure error in this situation. 

You can either measure the error in x, how close is x to x star, so kind of the norm of the vector that is the difference between x and x star, or you can look at the actual function error. How far off is f of x from f of x star? Those are both quite common. And so you'll see algorithms analyzed with either one of those two, whichever one is usually most convenient, used as a measurement of error. So these are common ways that we talk about how to characterize performance of iteratively converging algorithms.
