So maybe one of the most common is that if I take any two points in the set and connect them with a line segment, that line segment always has to lie within the set for the set to be convex. And you can see that that doesn't always happen in the non-convex case. Another few ways we can define convexity is that if you take any point on the boundary of the set and take a tangent hyperplane at that point, that's called a supporting hyperplane because in the case of a convex set, the entire set always lives on one side of that hyperplane. And that doesn't always happen in the non-convex case. If I took a tangent hyperplane at that point, it would cut through the set. It wouldn't contain the entire set on one side. Similarly, if I take a point exterior to the set, then in the convex case, I can always find what's called a separating hyperplane. 

It has the point on one side, and it has the entire set on the other side. And again, that doesn't always happen in the non-convex case. There are exterior points that you may not be able to separate from the set by drawing a single hyperplane. So these are a couple of common ways that we define convexity of sets. What does it mean now for a function to be convex? Well, here's a convex function, and here is an example of a non-convex function. So again, you can qualitatively see what's different here. 

And in fact, we can use the definition of a convex set to define a convex function. Because if you look at the space above a function that's called its epigraph, then if that space is a convex set, then your function was convex. And we can also import some of the ideas we just talked about for convex sets and talk about what they mean in the context of a convex function. So if I take any point on a convex function and I draw a tangent at that point, then this is, again, a supporting hyperplane. In the case of a convex function, that will be a lower bound on the function everywhere. It lies underneath the function. If I take any two points on a convex function and I connect them with a line segment, then that line segment lies entirely above the function in the case of a convex function. 

So there are a couple of nice properties here of convex functions. Another way that we often define convexity is using second derivatives. So in the simple one-dimensional case, when you're dealing with a function of one dimension, then if its second derivative is non-negative, then the function is convex. What does that mean if I draw, again, a picture of a convex function? Then the second derivative of that function is the rate of change of the derivative, and the derivative is just the slope of a tangent line to the function. So if I look at the tangent lines to my function, how they change as x increases, then you can see that those slopes are increasing as x gets bigger and bigger. Since the slopes are increasing, the derivative is getting bigger and bigger as x is increasing. 

So the second derivative is positive in this case. And that's the condition that we need for our function to be convex. So the second derivative has to be non-negative. If it is strictly positive, then we say our function is strongly convex. And if it's just greater than or equal to zero, then it's just convex. In the multi-dimensional case, if we have a function of several variables, then the generalization of this property, and this will look familiar if you've taken linear algebra. If not, then you may want to kind of separately kind of look up what these terms mean. 

The Hessian matrix, the matrix of all of the second partial derivatives of the function, that has to be a positive semi-definite matrix for our function to be convex. And if it is positive definite instead of positive semi-definite, then we are strongly convex. So that's basically the analog of the second derivative being non-negative condition. There are a few other things that we can say about the second derivative and the range of values that it takes that let us characterize what's called the condition number of our function. And that plays actually a very important role in the convergence rate of many algorithms. So it's worth defining. And typically, we define this in the case of a strongly convex function. 

So if the second derivative of a one-dimensional function lives in the range between little m and big M, then the ratio between those two numbers, big M divided by little m, that is the condition number of our function. And that's why it's important to be strongly convex, because we don't want little m to be zero, which would be a possibility if we were convex but not strongly convex. In the multivariable case, the analog of that condition is that the eigenvalues of the Hessian matrix of the function, they live in some range between little m and big M, where little m is a positive number if we're strongly convex. And so the ratio of big M to little m, again, is the condition number of our function. The closer the condition number to one, the better, generally, in terms of convergence, as we will see later on in the module when we talk about convergence rates of different algorithms. So important quantity to keep in mind, this condition number. This sort of idea of a condition number shows up a lot of functions in this case. 

And if you study numerical methods, kind of iterative methods for solving linear systems, you also have kind of an analogous notion of a condition number that often characterizes convergence rate of different algorithms. So if we talk about algorithmic implications of convexity, there are a couple of key ideas. And so, again, if we look at a convex function versus a non-convex function, maybe the biggest punchline of optimizing in the convex case is that a local minimum of a convex function is always going to be a global minimum of the function. And this is a big deal because often we base our optimization methods on iterative refinement. They kind of keep refining a set of guesses until eventually you converge to a locally optimal solution. And in the convex case, that will be the global optimum of your function as well, which is great. In the non-convex case, all you can say is that you will converge to a locally optimal solution, but it may not end up being the best global optimum available. 

And it's actually quite hard to find the global optimum of a non-convex function. All you can generally guarantee is finding your way into a local optimum with an iterative refinement-based approach. So that's a huge takeaway from a function being convex. If you are doing constrained optimization, so you want to minimize a function subject to a set of constraints governing which points in space are feasible choices, then it's much, much easier if you're optimizing over a feasible set of solutions that is a convex set. Otherwise, things get much, much harder from an algorithmic perspective. So kind of the easier, the tractable case of optimization, usually we think of that being the situation where we're optimizing a convex function over a convex set. That's usually where optimization runs relatively efficiently. 

Things get much more challenging if the function is not convex or the set you're optimizing over is not convex. Unfortunately, in practice, many of the functions that we're dealing with, like the loss function for a deep neural network, for example, they are not convex. And so we do have issues with finding only locally minimum solutions instead of globally minimum solutions. But it is nice to know kind of when our optimization methods end up being quite tractable in the convex case. And we can say some nice things about convergence rates in those situations as well. So we'll talk more about convexity as we move through the module, but it's good to know some of these preliminary ideas so that we'll be able to use them when we talk about analysis of our algorithms.
