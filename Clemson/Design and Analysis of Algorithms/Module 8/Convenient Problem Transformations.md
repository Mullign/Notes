If you're currently suffering from a bit of algorithm fatigue, don't worry. We promise in this video not to introduce any new algorithms. And that's kind of the point. What we're going to talk about instead is how to take a problem that is similar in structure to say a plain vanilla shortest path or max flow problem, and to kind of re-encode or transform the input of our problem so that it now can be solved with a plain vanilla off-the-shelf shortest path or max flow algorithm. It's usually much easier if we can do this using standard off-the-shelf algorithms and just changing our problem input slightly rather than having to reinvent the wheel and invent new algorithms for every single problem that we come across. I guess the adage here is change the problem, not the algorithm. So let's look at a few examples in the world of graph problems where we can do this. 

Our first example happens all the time in automobile transportation situations. It usually costs us more to turn left at an intersection than it does to turn right. And so suppose we'd like to solve a shortest path problem where we add an extra turning penalty constraint. Anytime we turn left, we would like for it to cost us an extra one unit of time. So if you represent your network in maybe the most straightforward way, it's hard to express that constraint. You might want to just represent an intersection with a node where edges coming in and out of that node represent, say, lanes of traffic that are going in and out of the intersection. If you do represent your graph this way, it's hard to express that particular turning penalty constraint. 

What we have to do instead is kind of refine our state space of nodes with a little bit more detail. So suppose we take what used to be our intersection node and think about kind of zooming in on that, blowing it up. And within that, we're actually now going to create nodes that represent the points of entry or exit of the different lanes coming in and out of our intersection. So we have maybe a lane coming into the intersection, a lane going out of the intersection. And now internal to that blown up node, we can now add edges that represent all of the possible turns. So a right-hand turn would give us a cost of zero, whereas a left-hand turn, maybe going left to this outgoing lane, maybe that costs us one. And so now we actually have the ability to express much more nuance in how much individual turns cost us. 

This is something we've done a lot with dynamic programming as well, kind of using a slightly finer grained state space of subproblems in order to express constraints that are hidden in our problem. Okay, let's take a look at another example here. So I go back to my slides. Because now, again, we're in the world of automobile transportation, we have a shortest path problem in an automobile network that some of the edges in our network cost us $1 toll, only a few of them, and we know which ones those are. We would like to find the shortest path in our network, say the path that takes us the minimum length of time to travel on, but we only have $3 in our pocket. So we can only afford to travel on three edges that are toll edges. So how do we find the shortest path subject to this extra constraint that we travel on at most three toll edges? 

That can also be addressed in a much, you know, very similar way to what we did before. So imagine that we draw a picture of our graph here. So here's our graph. And what I'm going to do is make a copy of that graph. In fact, I'm going to make a couple of copies of the graph. So I'm going to draw them kind of as layers, I guess, these kind of two-dimensional planar layers. I'm actually going to make three copies of the original graph and call those levels 0, 1, 2, and 3. 

So imagine that I have these three copies of my original graph kind of stacked on top of each other. And the entire graph exists in each of those layers. I'm not going to take the time to draw it all out in its full glory, but imagine that the entire graph exists in each layer. And now what I have is if I look at a toll edge, instead of that edge existing within a layer, each toll edge is going to kind of kick me up to the next highest level. So if this edge right here, for example, is a toll edge, then it's not going to exist within a layer, but instead it's going to take me up to the next higher level. So anytime I follow a toll edge, I end up at the same destination node, just one level higher. And if I'm in level 1, I end up in level 2. 

And this kind of represents the constraint of only allowing me to travel on three toll edges, because once you reach level 3, the toll edges are gone. You can't take any more toll edges at that point. So I've effectively turned every node into four nodes. Kind of imagine that instead of each node now, I have kind of four copies of that node representing not only what node I'm at, but what node I'm at, comma, how much money I have spent on tolls so far, and what level I'm at in this set of levels of graphs stacked on top of each other. And so I've just expanded my graph slightly. I've refined my state space of nodes so that now the constraint in my problem is represented within my graph itself. And I can just now apply a standard shortest path algorithm to this graph, and I don't have to change the structure of my shortest path algorithm. 

Okay, let's look at one more example. So suppose now that I have, again, a shortest path-like problem. So every single edge in my graph doesn't have a length or a cost or a weight associated with it. It has a failure probability. So each edge will independently fail with some specified probability. And I would like to find a path that, say, connects a source node to a destination node that has the greatest reliability. So the reliability of an edge is kind of 1 minus its failure probability, the probability that the edge remains intact. 

So how do I find a maximum reliability path given that I, as input, am provided with the independent failure probabilities of all the edges in my graph? So could we, for example, express that as a standard shortest path problem? It turns out we can. Let's take a look at how. So if I think about how to formulate that problem, I have my source node, I have my destination node, and I would like to find a path, let's call this path P, that has maximum reliability. So what is the reliability of a path? The reliability of a path is actually, let's call that the reliability of path P, that's actually going to be the product over all of the edges in P of the reliability of those edges. 

Because the only way that a path remains intact is if every single edge along that path remains intact. And so this is kind of a bunch of events anded together. Edge one has to remain intact, and edge two has to remain intact, and edge three has to remain intact, and so on. And so since these are all independent events, I multiply their probabilities together to get the probability that the entire path remains intact. And so what I would like to do is basically maximize over all possible paths P to find which one has the greatest reliability. And that looks a little bit weird because I'm used to solving shortest path problems. If I was solving a shortest path problem, the structure of this optimization problem would instead be minimizing over all paths something involving a sum of edge costs along the path. 

So here I'm maximizing a product of edge quantities instead of minimizing a sum of edge quantities. So how do I turn products into sums? All right, the standard trick here is take logs. And so what I'm going to do is instead of maximizing the reliability of a path, I'm going to maximize the log of that quantity. And remember that log is a monotonic function. So maximizing the log of something is the same thing as maximizing that something. So it doesn't make any difference if I insert a log at that location. 

So I'm trying to maximize the log of the product of all the reliabilities along whatever path I'm looking for. And the log of a product is the same thing as a sum of logs. So now this is equivalent to maximizing over all possible choices of path the sum over all the edges on that path of the logs of those reliabilities. So I'm almost there. This looks almost like a shortest path problem, just I'm maximizing instead of minimizing a sum of edge weights. And so how do you turn maximization into minimization? I'm just going to negate my edge weights, basically. 

And so that's going to be the same thing as now minimizing the sum of the, so minimizing over all possible paths, the sum over all the edges along my path of the negative logs of their reliabilities. Because maximizing something is equivalent to minimizing the negative of that something. And so all I'm going to do is treat negative log of reliability as the weight of each edge. And now I just solve the shortest path problem with respect to those new edge weights. Do I worry about negative edge weights being an issue here? I actually don't because reliabilities are probabilities. There are values in the range from zero to one. 

And so if I take the log of something in the range from zero to one, that gives me a negative number, but then I'm negating that negative number. So I actually end up with non-negative edge costs. So I can actually just use Dijkstra's algorithm to solve this particular problem. So again, I have a problem that maybe doesn't look exactly like a shortest path problem to begin with, but if I transform it in a clever way, I can actually turn it into a plain old vanilla shortest path problem and apply a standard shortest path algorithm to solve it. Okay. So these are a few examples from the world of shortest paths. Let's maybe look at a few examples in the world of flows. 

So if I go to the max flow problem, we're used to a standard max flow problem, having one source node and one sink node, and we'd like to find the max flow from the source to the sink. What if instead we have multiple nodes that could serve as sources and multiple nodes that could serve as sinks? That is, I can basically send flow out of any one of those sources and I can send flow into any one of those sinks. It turns out that's actually a very simple problem transformation away from a standard max flow problem with just one source and one sink. So if I have my graph and I have a whole bunch of different source nodes in that graph, then all I need to do is invent one kind of dummy super source node, and I will connect that to each of my individual source nodes with say an infinite capacity edge for each of these edges. So I can send as much flow as I want from my super source node to each of those individual source nodes. And then of course I do the same thing with my sink nodes. 

I have a couple of different nodes that could act as sinks, and so I will connect them to a dummy super sink node with a bunch of infinite capacity edges as well. And now I just solve a regular old max flow problem with that one super source and the one super sink, and it will route flow possibly through any of those individual source nodes or any of those original individual sink nodes. So very easy problem transformation. Max flow problems have a lot of these sorts of standard problem transformations that you can use to kind of turn one problem into another problem. Okay, here's a similar variant of the max flow problem. Suppose that instead of having kind of a source and a sink, I instead tell you for certain nodes in my graph that these are supply nodes, and I tell you how much of a commodity is being supplied at each of those nodes. And some other nodes in my graph are demand nodes. 

I have to ship the commodities from the supply nodes to the demand nodes. So maybe I have factories in my graph that are producing goods, and I know how much is being produced at each factory, and I have warehouses that I have to ship the goods to, and I know how much I have to ship to each warehouse, and I'd like to find a flow that satisfies those kind of supply and demand values. So what that looks like is basically, again, I have a graph, and every single node in the graph has an extra number attached to it, like plus five. This would be a supply node from which five units of commodity are being emitted. So if I look at the flow conservation constraint on that node, I have to make sure that I send out five more units than I take in from that node, because flow is being produced at that node. If I have another node that has, say, a negative value associated with it, that's a demand node. That's a node that has to take in seven more units of flow than it puts out. 

And so basically, I have to ship flow from all of the positive supply nodes to all of the negative demand nodes. The sum of all the positives had better equal the sum of all the negatives, otherwise there wouldn't be a possible solution for routing all of the flow. So again, if I have a problem like this, I can apply a very similar transformation to what we just did. Suppose I have two supply nodes with supplies of plus five and plus three. I'm going to just introduce a dummy super source node, and I'm going to connect it to each of those supply nodes. And now I'm going to set the capacities of those edges equal to the supply values. So capacity five connecting to the node that has to have, you know, five units being emitted from it and capacity three for the edge that goes to the node that has a supply value of three. 

I do the same thing for the demand node. So if I have two demand nodes of, say, demands negative seven, and I guess I'd have to have negative one because the total supply has to equal the total demand. Then I introduce a dummy sink node, and I'm going to connect my demand nodes to the sink node with edges having capacity that matches the demand values of those nodes. And now I just solve a max flow problem from the source to the sink. And if the max flow is able to saturate all of the outgoing edges of the source, which is equivalent to saturating all of the incoming edges to the sink, then the solution within the original graph will actually solve my problem. I will have five extra units of flow being emitted from the supply node with a plus five on it, for example. So a very simple transformation that lets me solve a problem very similar to my standard max flow problem. 

Let's look at maybe just one other nice common transformation that we see with max flow problems. So most max flow problems have capacity constraints on edges. What if instead we have a capacity constraint on nodes that governs how much flow can go through a node instead of through an edge? So how could we encode that in a way that lets us solve this problem with kind of a plain vanilla max flow algorithm? This is also relatively straightforward. What I can do is something reminiscent of what we did with the automobile transportation application. So if I have, say, a node, then that node has incoming and outgoing edges, and I have maybe a capacity constraint on that node saying that I'm allowed to send maybe at most seven units of flow through that node. 

So how do I transform this situation back into a situation with edge capacities, which is what I need for my regular old max flow algorithm to work? So the standard transformation here is called a node splitting transformation. I'm just going to take my node and split it into two pieces. One of them represents kind of the incoming side of the node, and one represents the outgoing side of the node. And so my two incoming edges are going to be incoming to the incoming side of the node, and my three outgoing edges, they're going to be outgoing from the outgoing side of the node. And I'm just going to now put an edge between the two of those with a capacity of at most seven. And so kind of, I've again, basically taken what used to be one node and kind of blown it up into multiple nodes in almost the same way that we did with the left turning constraint example. 

And so now I have a capacity constraint on an edge instead of on a node. So these are just a few examples of types of common problem transformations that you might want to apply so that you don't have to keep changing your algorithms around. You can just use off-the-shelf algorithms to solve these problems that are very similar variants of standard problems.
