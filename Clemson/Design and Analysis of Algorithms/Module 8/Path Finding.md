In our discussion of depth-first search so far, we've addressed the question of determining if two nodes are connected by a path, but we haven't yet talked about how to find such a path. It turns out that's actually relatively easy to do, so let's show how to update depth-first search to find an actual path connecting two nodes. This works in an undirected graph or in a directed graph. All we need to do is when we take a step from one node to another in depth-first search, we keep a parent or a back pointer or a predecessor pointer going back to where we came from. So if we step from node I to node J at some point during the depth-first search, then we just set J's predecessor pointer back to I. So we kind of keep track of, for each node, how we got to it via the depth-first search process. And so if we do this simple update to depth-first search, then in order to find a path from, say, node I to node J, all you do is launch a depth-first search at node I that will fan out and visit everything reachable from node I, hopefully including node J if it is, in fact, reachable by some path, and then you just recover the path in reverse by starting at J and following those predecessor pointers backwards until eventually you reach I. 

In fact, these predecessor pointers have a very nice structure. They actually form a tree, a directed tree. Sometimes it's called an arborescence, which is rooted at node I, the place you started the depth-first search, because all predecessor pointers or parent pointers eventually lead you back to node I. And so this is actually a very common feature with many sorts of path-finding algorithms. We'll see the same phenomenon when we study breadth-first search and Dijkstra's algorithm and other shortest path algorithms that find the shortest path from a source node to every other node in a graph. All of these algorithms will allow you to recover the paths by keeping track of these predecessor or parent pointers that basically tell you for each node how you got there. And in fact, we talked about a similar phenomenon with dynamic programming.
