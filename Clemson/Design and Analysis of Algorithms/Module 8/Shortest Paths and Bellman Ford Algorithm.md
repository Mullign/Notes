One of the challenges with learning about shortest path algorithms is indeed that there are quite a few different shortest path algorithms out there to learn. And we have to make sure that we're always applying the appropriate algorithm for whatever problem variant is in front of us. Just to review the landscape so far, we've already learned how to use breadth-first search to solve shortest path problems in linear time in an unweighted graph. We've learned how to use dynamic programming to also solve shortest path problems in linear time in a directed acyclic graph, in a DAG. And most recently, we've learned how to use Dijkstra's algorithm to solve shortest path problems in almost linear time if we happen to be lucky enough to have non-negative edge costs. And that's a very common special case that we see a lot in practice. So these three variants of shortest path algorithms are probably the most common that you'll encounter in practice. 

If you have to only remember three shortest path algorithms, these are probably the three that you want to remember. However, we do want to make sure that our toolbox is complete. And so it's nice to at least know of an algorithm that we can use in the event that we have to solve a shortest path problem that involves negative edge costs. And our go-to algorithm in that case is going to be called the Bellman-Ford algorithm. The subject of this short video. The Bellman-Ford algorithm is actually a very simple algorithm to understand and to code. It's just not particularly fast. 

And so we want to make sure that we only apply it when we need to, when we have negative edge costs present in our graph. Remember also that if you have negative edge costs present, we at least have to kind of insist by assumption that there aren't any negative cycles in our graph. Because if there is a negative cycle in your graph, then the shortest path calculation becomes pretty much intractable. It's hard to even define shortest paths because a shortest path would want to go around a negative cycle an infinite number of times on its way to its destination. Conveniently though, the Bellman-Ford algorithm can at least detect the presence of negative cycles. So it will either calculate shortest paths from the source to all other nodes, or it will throw up its hands and say, sorry, I found a negative cycle. I can't calculate shortest paths properly. 

So let's dive in and have a look at the algorithm. As I mentioned, it's a very simple algorithm. It's based on the principle of edge tightening, just like Dijkstra's shortest path algorithm. So we're going to initialize a cost label for every node, just like with Dijkstra's algorithm, the source node starts out with a cost label of zero, and every other node in the graph starts out with a cost label of infinity. And then we just tighten edges over and over again. We're going to make a pass over every edge in the graph and try tightening all those edges that is looking for violations of the triangle inequality. And whenever those are found, we use those to improve, i.e. lower the cost labels of certain nodes. 

So we make a pass over all the edges, try tightening them, and we do that n minus one times. And that is the Bellman-Ford algorithm. It is a very straightforward algorithm. The running time is actually quite apparent because you're making n minus one passes, and in each pass, you're scanning over every single edge in the graph and trying to tighten it. Tightening an edge just takes constant time. And so the entire running time of the algorithm is order of m times n, number of edges times number of nodes. This is substantially slower than all of the other algorithms we've seen so far, Dijkstra's algorithm, breadth-first search, and the like. 

And so we definitely want to make sure we only use this algorithm when it is called for. Also, I mentioned that we can detect negative cycles. That's easy to do because after running n minus one iterations of the algorithm, if you make just one more pass over all the edges in your graph, and you notice that there are still violations of the triangle inequality, that can only be the case if there was a negative cycle in your graph. So in that case, you can just print out, sorry, there's a negative cycle in my graph. I know that my edge cost labels are probably not going to be set correctly because there's no good way to define shortest paths in that situation. So that's how you at least detect the presence of a negative cycle. Correctness of the algorithm is also relatively straightforward to establish. 

There are a couple of nice ways you can argue this. Actually, the Bellman-Ford algorithm has a very nice interpretation as a dynamic programming algorithm. I think I'll maybe not talk about that way of analyzing it, but instead talk about another very simple way that we can kind of argue correctness of the algorithm that's a little more kind of just based on mathematical induction. We kind of argue that after k passes of the algorithm, we will have at least discovered shortest paths of k or fewer hops. So maybe I can draw a picture of that to convince you how that works. So if I switch over to my whiteboard here, then let's look at kind of a generic shortest path in our graph. So suppose I have my source node and then a shortest path that goes to node one, node two, node three, and then finally to some destination node J. So this is just an arbitrary generic shortest path in my graph. 

And maybe I'll assign some costs to these edges, maybe seven, three, two, and five. So now if I look at the initialization of the Bellman-Ford algorithm, it's going to assign cost labels to all of my nodes. So initially a cost label is zero for the source and infinity for all of the other nodes in my graph. So that's the initial state of the Bellman-Ford algorithm. After the Bellman-Ford algorithm makes one pass over all of the edges in the graph, it's going to at some point examine the edge of cost seven and try tightening that edge. And when it does that, it's going to correctly establish the cost label for node one as seven. So node one is going to be correctly set to its proper shortest path cost after one pass of the algorithm. 

After another pass of the algorithm, now that node one is set correctly, we will at some point examine the edge of cost three that goes from one to two. And in so doing that, we will set the cost label of node two to its correct value, that is seven plus three, which is 10. And so after two passes of the algorithm, we are guaranteed to have the first two cost labels along this path set correctly. And so basically that's the way we're going to argue this by induction. After K major passes of the algorithm, the first K nodes along this path are going to have their cost labels set correctly. In fact, if we're lucky and we examine the nodes, if we try tightening the nodes in an order that corresponds to the order going down the path, then just one pass of the Bellman-Ford algorithm would actually set all of those cost labels to be correct, but we can't really guarantee that. This has to happen for all the different shortest paths in our graph all at the same time. 

So the best you can hope for is basically kind of making progress at the rate of one node per pass of the algorithm. And we know that in any shortest path, there are at most n minus one edges. That's why it takes n minus one iterations of the Bellman-Ford algorithm to guarantee that you finally make your way to the end of every shortest path and set all of the cost labels appropriately. So after n minus one passes, all of the cost labels in our graph will be set correctly. And the only way they wouldn't be, the only way that we would still have edges that violate the triangle inequality is if we happen to have a negative cycle in our graph. So that's the Bellman-Ford algorithm. One optimization that is common with this algorithm is that if you ever make a pass over all of the edges in your graph and you notice that the cost labels don't change, then you can terminate the algorithm early. 

And that happens a lot in practice. You may not need to make all n minus one passes. You can stop early if you're lucky enough to have fixed all the cost labels with a smaller number of iterations. So that's basically it. That's the Bellman-Ford algorithm. It's a relatively straightforward algorithm, but it's good to know about if you do happen to encounter a shortest path problem with negative edge costs.
