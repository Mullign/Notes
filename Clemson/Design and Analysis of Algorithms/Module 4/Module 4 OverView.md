![[Module 4 Overview slides.pdf]][Music] Dean: Welcome to Module 4 on the foundations of data structures. This is the first of two or three modules where data structures will be in the spotlight. I think here the word foundation is important. It's the right word to use because if you really do want to develop genuine expertise as an algorithm designer, then it has to be built on a foundation that includes expertise in data structures. Why are data structures so important? They are absolutely foundational in algorithm design. There are a vast number of algorithms out there for which the performance of the algorithm is largely determined by the data structure that it uses. 

Many fast algorithms have data structures to thank for their remarkable performance. It's very hard to be an effective algorithm designer, if you don't have a strong repertoire of data structures and you don't understand how you can store and manipulate data in memory. Also, many modern programming languages support pre-built data structures of all sorts. They have existing implementations of most of the major data structures, and those are perfectly fine to use. I encourage that because that lets you more easily develop sophisticated algorithms. However, if you don't understand what's actually happening underneath the hood, then there's the potential to misuse those data structures. Oftentimes I see novice students writing code that surprises them in how slow it runs because they don't realize that the data structure they're using isn't quite the right one for the task, or that there's some operation on that data structure that they don't realize is running much slower than they think it should be running. 

Having a strong knowledge of data structures, lets you really understand the pre-built data structures that you're using, so you can use them as effectively as possible. Then finally, algorithms and data structures, they just go hand in hand in terms of design and analysis techniques. You can learn a lot by studying data structures that can then help you be a better algorithm designer. There are lots of interesting analysis techniques that data structures really highlight very beautifully that when you study data structures, you could learn about and then port those types of techniques to the analysis and the design of future algorithms. A lot of benefit comes from studying data structures. If I had to list maybe the top three data structures to remember after taking a course in algorithms and data structures, the three that you're maybe the most likely to see in the future or to use in your implementations, this would be my top three list. The binary search tree, which is really maybe the most versatile data structure out there, the hash table, which also includes hashing in general as an algorithm technique and the binary heap. 

These are the big three in my opinion. Two of them will be covered in this module with hashing covered later in the course rather extensively. Just this set of three data structures will give you basically the ability to implement almost every abstract type of data structure that you could imagine, you can implement sets and maps and priority cues and sequences and whatnot. There's a tremendous amount of power that you get even by just having a baseline level of expertise in just these three fundamental types of data structures here. We'll cover these in a fair amount of detail, including hash tables later on in the course, and that will be a baseline for everything that we do with our algorithms moving forward. What are we going to learn in this module? Well, like I said, we're going to focus on two main types of data structures, binary heaps and binary search trees, probably spending the most time on binary search trees because there's a lot of fine grained detail to talk about there, like how to keep them balanced, how to use them as not only sets and maps, which are maybe the most standard ways of using them, but you can also use them to encode sequences.
