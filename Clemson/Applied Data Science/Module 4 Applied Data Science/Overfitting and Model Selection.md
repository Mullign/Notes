So we can see that with the more degrees of polynomial specificity, we can have a exponentially growing mean square error. We do not want to have just as many polynomial degrees as we want. So how do we actually report back the performance of the model? Well, we split up our full data set into training, testing, and validation. We say that we have an error with the test set of 0.52, for example, and with a degree one polynomial, our error on the training set, just mean square error, totally normal error approximation number, having 0.83. So we know that overfitting is a possible problem here, and we need to have some sort of way to choose between which model we're using. Model selection is the application of a principled method to determine the complexity of the model. 

So choosing a subset of the predictors, choosing the degree of polynomial, all of the meta decisions that we make before we actually get into the hard and fast statistical drawing lines on a graph. So strong motivation for the performing model selection is to avoid overfitting, which explodes our error. If we have too many predictors, we have a feature space with a really high dimensionality and therefore is hard to compute on. The polynomial degree is too high, leading to overfitting, too many cross terms are considered. The coefficient values could be just too extreme, too. We'll talk about that when we get in a little bit. So how many different models should we consider when we have j predictors of our data set? 

When we have j predictors to use in our models, we have 2 to the j number of models to choose from. So for example, if we have three predictors, if we only use one of them, we can choose x1 or x2 or x3 to predict. If we have no predictors, we have a very easy decision to pick from. So we have three pair of predictors, m4, m5, m6, and then finally, every predictor being used at the same time, m7, we have a total of 2 to the 3 models, 8 models. So our first way to pick which model we're going to be using is with stepwise variable selection and cross validation. Basically we take the subset of predictors and iteratively build an optimal subset by choosing a fixed model evaluation metric as we build it up. Here's an algorithm to show this forward method here. 

We have an optimal set in parentheses because there are some edge cases that we'll need to be considering later. The way this works is that we start off with the empty set. Every set of predictors has choosing none of them as an option. And then we add in predictors. First we add in one predictor. So for k equals 1 to j, we're going to loop over the number of predictors we have. We choose a model to be the model constructed from the best set of predictors. 

So starting off with one predictor, we choose whichever one predictor has the best metric associated with it. We select the predictor not in the set so that the model constructed when we union them together optimizes that metric. We pick a different predictor that is not already being used and whichever predictor has the greatest impact on our model to be the lowest error. We choose that and add it into our model. And we keep building this up until we have reached all of our numbers of predictors. And then we select the model that optimizes the metric that we're using. So we've been using MSE for a lot, but there are other metrics to be considering as we build up these models. 

So we're evaluating a lot of models here. We're trying to figure out the error evaluation of each of these models. We need to think about the computational complexity, how expensive is it to actually use this method and figure out which of our models is optimal under our metric. So as it turns out, when you evaluate j models in the first iteration, j minus 1, in the second j minus 2, and so on, we get a big O of j squared complexity, which is way, way less than 2 to the j for large j. And in this case, large j here means j equal to or greater than 5. You will find it very, very infrequent in the real world to be working with data sets with fewer than 5 predictors.
