​So let's first talk about heuristic evaluation. ​Heuristic evaluation is a usability inspection method that was developed by Jacob Nielsen, ​a very famous HCI person and his colleagues, ​and was later modified by other researchers for ​evaluating specific types of software systems. ​So the method is based on heuristics or best practices and ​principles distilled from an empirical analysis of 249 usability problems. ​So experts guided by a set of usability principles known as heuristics, ​evaluate whether user interface elements such as the dialog boxes, ​menus, navigation structure, online help, ​and so on can conform to tried and tested design principles. ​So the heuristics have been revised for current technology by Nielsen and others, ​that are categorized for mobile devices, ​heuristics that are categorized for wearable devices, ​heuristics that are categorized for virtual worlds, ​augmented reality, etc. ​These heuristics closely resemble high-level design principles. ​Examples of which include things like making designs consistent for ​mobile applications so that users can use existing knowledge of ​using mobile applications for use in the current product, ​and reducing the memory load associated with knowing how to use a product, ​and using terms that users understand ​in the context of how information is presented to the user. 

​So the design guidelines form a basis for developing these heuristics. ​So knowing design guidelines like affordances, feedback, mapping, etc, ​that we have studied in the design of everyday things, ​and minimizing the gulf of execution and evaluation. ​All these design guidelines actually go into the development of these heuristics, ​these design principles that are actually used ​towards evaluating the interfaces by the experts. ​Here are example design heuristics for a class of applications that is ​found in the revised version of Nielsen's 2014 original heuristics. ​So one of the heuristics is visibility of system status, ​which means that the system should always keep users informed about what is going on ​through feedback and in reasonable time without any lag. ​Match between system and real-world, ​which means the system should speak ​the user's language with words and phrases and concepts familiar to the user. ​User control and freedom, that is, ​users often choose system functions by mistake and will need to ​clearly mark emergency exits or leave ​the unwanted state without having to go through an extended dialogue. 

​Consistency and standards. ​Users should not have to wonder whether different words, ​situations, or actions mean the same thing as what they are used to. ​Error prevention, that is, ​eliminating error-prone conditions or check for them and ​present users with a confirmation option before they commit to an action. ​That's a form of error prevention that is a good design principle and design guideline. ​Recognition rather than recall. ​So being able to promote or minimize ​users' memory load by making objects, actions, and options visible. ​That is, the user should not have to remember ​information from one part of the dialogue to another.
