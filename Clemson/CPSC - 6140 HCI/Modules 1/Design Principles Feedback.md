![[Design Principles Feedback Slides.pdf]]So we have looked at visibility as a design principle. Let's next look at feedback. Feedback has to do with sending information back to the user with regards to the result of an action. So what's implicit here is that the information provided has to be immediate about what has been done at the system. So feedback has to be immediate, and this includes also multimodal feedback, which includes aspects such as sound, highlighting, haptic feedback, perhaps animation, combination of these to explicate the fact that the input has been processed and the system is getting ready to guide the next interaction. So if there's actually a delay in terms of providing feedback to the user, and if it is not immediate, then that could be one of the impediments to the system. So imagine that you have a online shopping website in which the user has to enter their credit card information, and they click submit. But since the feedback is not immediate, the user might click submit two or three times, and in the process, the online shopping website might process their payment two or three times. So they might be charged twice or three times as much for that product because they clicked multiple times. So feedback needs to be immediate, and a good design principle is to provide the feedback in a multimodal fashion that involves sound, highlighting, some sort of haptic feedback, if possible, animation, combination of these. When a screen button is clicked on and it provides sound or a red highlighted feedback, then it is immediate. It provides some information immediately back to the user, saying that the button press was processed and was received by the system, and the system is now computing what should be the next information that should be provided back to the user, and is computing based on the user's feedback.
