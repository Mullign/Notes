Consistency as a design principle has to do with design interfaces for similar tools to be designed in a similar manner, such that the experience from a similar such tool in the past or earlier of such a tool can be applied in the next version of that tool. An antiquated example of that tool can be applied to the new tool or to an improved tool, for example, the knowledge from that prior tool can be applied to the following tool. So if you want to design interfaces to have similar operations or use similar elements for similar tasks, one example is always to use the control key plus the first initial of the command for an operation for copying, for saving, for opening a file, for example, for these kinds of things. So this allows for an interface to use the same sort of command sequence for different operations using the system. So that allows for consistency. The main benefit of consistent interfaces are that it's easier to learn, it's easier to use, because once you have learned that control plus the first letter of a certain command performs that command, then you can apply it consistently for other such control situations. When consistency breaks down, what happens if there is more than one command starting with the same letter, for example, save, spelling, select, and style? Here, it's not so obvious anymore, and you have to find other initials or combinations of keys, thereby breaking the consistency rule, such as, for example, for save, it is control plus S, for spelling, it could be control plus SP, or for select, it could be control plus shift plus L, etc. Then it gets really complicated, that is hard for the user to remember. And it affects the learnability as well as the memorability, because it makes those aspects of usability more complicated, and increases learning burden on the user, making them more prone to error. Internal and external consistency is something that I mentioned earlier. Internal consistency refers to designing operations to behave the same within an application, such as the example of the control plus the first letter of a command that is used consistently from one command to another. External consistency refers to designing operations interfaces to be the same across applications and devices. So accounting software as a whole, having specific types of operations that are conducted in a similar way, such that if you encounter a new accounting software, you can use your knowledge of how you operated the interface of a previous accounting software on the new application. So it is rarely the case because different designers have different preferences, and different designers have different proprietary designs. So external consistency oftentimes falls through the cracks, and is a design principle that is not often observed by designers. Keypad numbers layouts is a good example of external inconsistency. So on phones, remote controls, for instance, you have the layout that is shown on the left here. And when it comes to calculators and numerical keypads on a computer, the numerical layout is different than that of phones and remote controls. So this actually breaks the external consistency rule. And so users have to, you know, go between learning the numerical layout of one particular class of systems from that of a different class of systems. So they can't really take the knowledge and experience that they have gained from one particular class of controls and apply it to a different setting.
